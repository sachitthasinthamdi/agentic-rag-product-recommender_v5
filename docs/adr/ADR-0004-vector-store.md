# ADR-0004 — Vector store: ใช้ Chroma local อย่างเดียว

- **สถานะ:** ✅ **ตัดสินแล้ว** (ผู้ใช้เคาะ 2026-09-28)
- **การตัดสิน:** ใช้ **ChromaDB แบบ local (`PersistentClient`)** เท่านั้น — **ไม่ใช้ Chroma Cloud**

## บริบท

mark4 ใช้ Chroma local แล้ว sync ขึ้น Chroma Cloud เพื่อให้เพื่อนร่วมทีมเข้าถึงดัชนีได้
โดยไม่ต้อง build ใหม่ แต่มีต้นทุนและข้อจำกัดตามมา

## สิ่งที่ได้จากการตัดสินนี้

| ประเด็น | ผล |
|---|---|
| ค่าใช้จ่าย | **$0** — ไม่ต้องใช้เครดิต $1.75/sync และไม่ต้องไปเช็คยอดเครดิตคงเหลือที่ค้างอยู่ |
| เพดาน 300 record/request ของฝั่ง cloud | **หายไป** — เขียนเป็นก้อนใหญ่ได้ ลดเวลา index |
| ขั้นตอน `sync_to_cloud` | **ไม่ต้องมี** — ลดโค้ดและลดจุดที่พังได้ 1 จุด |
| ข้อมูลออกนอกเครื่อง | **ไม่ออกเลย** — สอดคล้องกับที่ระบบใช้ LLM local อยู่แล้ว เขียนในเอกสารธรรมาภิบาล (ด่าน 15) ได้ตรงไปตรงมาว่าไม่มีการส่งข้อมูลไปบุคคลที่สาม |
| API key ใน `.env` | **ไม่ต้องมี** — ลดความเสี่ยงเรื่องความลับหลุด |

## สิ่งที่เสียไป และวิธีรับมือ

**เพื่อนร่วมทีมเข้าถึงดัชนีเดียวกันไม่ได้ทันที** ซึ่งเป็นเหตุผลเดียวที่ mark4 ใช้ cloud

รับมือด้วย 2 ทาง:
1. **คัดลอกโฟลเดอร์** `data/embed/chroma/` ให้กันตรง ๆ — Chroma local เก็บเป็นไฟล์ ก๊อปได้เลย
2. **สร้างใหม่จาก pipeline** — `python -m mark5.data.pipeline` แล้ว index ใหม่ ใช้เวลาประมาณ
   84 นาที (ทุกอย่างทำซ้ำได้จาก `manifest.json` ที่บันทึก revision + sha256 ของต้นทางไว้)

ข้อนี้รับได้เพราะ mark5 เป็นงานวิทยานิพนธ์ที่รันบนเครื่องเดียว ไม่ได้มีทีมพัฒนาหลายคน
ทำงานพร้อมกัน — ต่างจากสมมติฐานเดิมของ mark4

## ผลกระทบต่อเอกสารและโค้ด

- `config/settings.py` — ตัด `CHROMA_API_KEY` / `CHROMA_TENANT` / `CHROMA_DATABASE` ออก
  และเปลี่ยน `CHROMA_MAX_BATCH` เป็น 5,000 (จำกัดเองเพื่อคุมหน่วยความจำ ไม่ใช่ข้อจำกัดของ Chroma)
- `.env.example` — ตัดหมวด Chroma Cloud ออกทั้งหมด
- `01_objectives.md` — ตัดงบ sync cloud ออก และปิดรายการค้างเรื่องยอดเครดิต
- **ไม่ต้องเขียน** `sync_to_cloud.py` (mark4 มี, mark5 ไม่มี)
